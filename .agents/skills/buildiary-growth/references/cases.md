# 診断例と失敗例

以下の数値・URL末尾は**合成教材**。サイトの実績ではない。

## 例1：モデル記事 0 clicks / 40 impressions

原値：page集計0/40、query集計「example model」0/18。page×query取得前。

失敗：「titleが悪い。変更すればCTRが上がる」。別集計の対応関係と原因を同時に発明している。

診断：query×pageを追加取得。公式モデルページが検索者の求める定義を直接返すか、自サイトに制作判断・検証用台本があるかを照合する。titleに定義と制作価値が既にあれば、title変更の順位を下げる。比較表で答えられない制作タスクがあればその節を作る。0/40は独立同分布と仮定しても幅が広く、原因は特定しない。

採用案：公式と同じ機能紹介の新記事は見送り、既存記事で音声をゲーム内へ入れるまでの確認手順を補う。生成を試していなければ、試聴実績と書かない。

## 例2：hub 90 PV、記事 3 PV

失敗：「遷移率3.3%、一覧を全面改修」。一人のカテゴリ操作が複数PVになりうる。

診断：コードでpushState/replaceState、GA設定でhistory計測を照合。hubは要約カード、本文は独立routeと確認。セッション単位の一覧露出と実リンク操作が未取得なら、遷移率は作らない。公開画面でリンクが機能するかを直接調べる。

採用案：読者の目的に対してカードの成果物説明が具体的かを検証し、必要箇所だけ差分化。UI故障を確認した場合は、効果推定を待たず修復する。

## 例3：保存ガイドはあるが公開手順がない

原値：合成page Aに70 PV、query「ゲームを公開」3 impressions。query×pageの実対応は別途取得。

調査：自サイトの節はファイル保存で止まる。公式はsource branch/folderとentry fileの一致が必要と説明。競合の制作者記事は公開URLまで提示するが、コマンド操作が中心。

採用：既存URLに「Web画面だけで、保存したbranchから公開し、URLで再プレイする」節を追加。new branchへ保存した読者へmainを無条件に案内しない。404ならbranch/root/index.html/ビルド結果へ戻す。Private repoでもサイト公開範囲を別に確認する。

見送り：新しい一般入門記事は既存の解説と重複。title全変更は検索意図の追加対応を先に作る。SNS一斉投稿は送客先の有用性確認後の別作業。

観測：一連の手順で読者が公開元とURLを見つけ、別タブで操作できるかを確認。その後、記事のengaged sessionsと検索clickを別々に追う。少標本の前後差を施策の因果効果と断定しない。失敗時は同じ案の再命名ではなく、止まった手順を修正する。

## 例4：本人の作品を使えば新しい獲得案になるか

原資料：本人の既存記事に、手元の端末とクラウドの役割、具体的な表示問題、同じ場面の再確認、初心者練習へのリンクが既にある。自サイトにはその一部だけがある。

失敗：自サイトへ同じ経験を再編集し、空欄の修正カードを付け、『新しい独自価値を持つ主獲得実験』とする。本人の実作品と配布先があっても、読者が新たに得るものが一般的なカードだけなら、元の記事との差は弱い。

診断：自サイトの未掲載と、既存の本人コンテンツを含めた新規価値を分ける。`coverage=missing`でも`delta_status=duplicates_existing`なら獲得実験から外す。流入総計を変えず、この独立反例を根拠へ反映したときに候補が除外されるルーティングを検査する。コードは原文の意味を自動判定したのではなく、原文の診断は別担当が照合する。

次の調査：公開リポジトリの実コミット、症状を再現できる前後版、差分が守る動作、読者が同じ問題を観察できる実物を探す。出典に追えるコードと再現結果が得られた場合にだけ新しい差分として再提案する。コミットだけで画面の成功を実証した扱いにはしない。転載・カード増量・title変更で棄却をすり抜けない。


## 例5：PV案から購入判断へ変えれば収益主軸になるか

原資料：架空の既存体験記事には実行できる完成例がある。有料素材ツールの公開報酬は率制だが、個別契約・対象純売上・継続・承認/支払実績は未取得。必要な素材を一度作れば解約後も使える条件があり、継続購入の理由は未確認。

失敗：無料体験のPVを成約見込へ変換する。次に、有料意図のある記事へ変えただけで事業主軸とし、定価×率×最大報酬月数を全員のLTVとして投資を正当化する。

診断：前のPV案、最低必要契約を選ぶ既存記事の小改善、繰返し素材が必要な読者への総費用比較を同じ費用/期間条件で比較。初月割引と通常更新を別scheduleにし、単月/複数月で必要な承認成果数を計算する。個人率が未知なら公開率を仮定として保持し、支払済み実績にはしない。時間単価・維持負担が未知なら経済費用は式のまま示す。

採用：一度だけの小さな購入支援は低工数検証枠へ下げ、繰返し制作の読者と無料/有料既製/生成＋後処理の比較を研究候補にする。ただし支払理由と導入工数が未確認なら研究枠にとどめ、事業主軸の確定とはしない。無料既製で足りる場合や後処理で不利なら推薦を取り下げる。

検証：同じ原観測を保持したまま、収益条件と費用によって前主戦略の採否が変わる理由をprivate briefで説明する。計算や必須項目のpassだけを戦略の意味的優越の証明にしない。
