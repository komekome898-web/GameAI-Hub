# 友達に渡すゲーム紹介のひな型

この文章をコピーして、分かる範囲で記入し、横長16:9の画像を1枚添えて運営へ送ってください。タイトル画面やプレイ中のスクリーンショットで構いません。GitHubアカウントやCMS登録は必要ありません。未確認の項目は「未確認」と書いてください。

```text
ゲーム名：
公開する作者名：
遊ぶURL（https）：
ひとこと紹介（1文）：
ジャンル：
どんなゲーム？（2〜3文）：
見どころ（3つまで）：
遊び方（ゲームを開いてから始めるまで）：
操作（タッチ／キーボードなど）：
想定するプレイ環境・画面向き：
確認した端末・ブラウザ・画面向き・確認日：
料金・課金の有無（未確認ならその旨）：
アカウント登録の条件（必須／任意／未確認、用途）：
使ったAIと、それぞれに任せたこと：
人が確認・調整・工夫したこと：
SNS（任意）：
制作体験の記事URL（任意）：
画像の説明（何が写っているか）：
画像の作者・必要なクレジット：
紹介文をサイトへ掲載してよいですか？：
添付画像をサイト・紹介カード・SNS向けOG画像に掲載してよいですか？：
文章・画像の第三者素材、必要な許可・クレジット・利用条件：
```

許可が確認できない文章や画像は公開しません。ゲームのすべてをAIが自動で作ったと誤解される説明は避け、AIと人の役割を書いてください。画像には個人情報、秘密、掲載許可のない第三者素材を含めないでください。

## 運営が作品を追加する手順

1. 受け取った文章・画像と遊ぶURLを確認する。リンク先を実際に開き、対応環境や操作の根拠を残す。未確認の料金・登録・端末対応・素材権利を推測で埋めない。必要なら作者へ質問する。
2. `public/images/games/<slug>/` に画像を保存する。実寸を確認し、元画像の縦横比を `width` / `height` に記録する。スクリーンショットのピクセルを確認し、画像説明とクレジットを合わせる。
3. `data/games.ts` の `games` に `GameRecord` を1件追加する。既存作品を参考にし、英小文字・数字・ハイフンの重複しない `slug`、`order`、受領内容、根拠リンクと確認日を記入する。`publicationStatus: "draft"` から始める。TSXを複製する必要はない。任意のSNS・制作記事は、なければフィールドを省略する。制作記事はサイト内の公開記事、または確認済みのhttps外部記事をリンクできる。
4. URL・画像・文章画像の掲載許可と必要なクレジットを確認する。`publicationReview` は運営の確認結果として記入し、未確認の項目は `false` にする。
5. ローカル作業ブランチ内で一時的に `published` にし、`npm run dev` で `/games/<slug>/` と `/articles/#games` をプレビューする。draftは公開一覧・詳細ルート・sitemapに出ない。プレビュー後はdraftに戻し、画面や文面を作者・運営責任者に見せて承認を受ける。未承認のpublished状態をpushしない。
6. 承認後に `publicationReview.approved` と `publicationStatus` を更新する。`npm run validate:games`、関連テスト、`npm run quality`、`npm run build` を実行する。375pxとdesktopで画像・日本語・紹介/遊ぶ・戻るを確認し、変更と画像を同じPRでレビューする。公開は別途承認されたマージで行う。自動公開はしない。

共通ページは `app/games/[slug]/page.tsx`、共通カードは `CreationDeck` を使う。公開作品の一覧・カテゴリ件数・静的ページ・metadata/OG・sitemapは同じデータから生成される。0作品は準備中、1〜2作品は一覧、3作品以上は既存カードの安全条件を満たせば円環表示になる。作品は「すべての記事」の件数に含めない。制作記事を作る場合は記事レジストリのpracticeへ登録し、作品データから任意リンクを張る。
