# AIで作ったHTMLゲームが動かないときの直し方 草稿

ボタンが反応しないときは、押した順番とConsoleの最初のエラーを記録します。ここでは「AIでブラウザゲームを作る方法」の掲載完成例に、不具合を1つずつ入れて確認しました。自分のゲームの変数名やHPが違う場合は、同じ数値へ直す必要はありません。

## まず動いた版で操作の基準を確かめる

掲載例の初期HPは、ゆうしゃ24／スライム18でした。「たたかう」を1回押すと20／12、2回で16／6、3回で16／0になり、「スライムに勝った！」と表示されました。最後の攻撃で敵が倒れるため、その回は反撃がありません。勝利後は攻撃できず、「もう一度」で24／18に戻り、2周目も同じ順番で勝てました。

直した後も、初回の起動だけで終えず、攻撃→勝利→攻撃停止→もう一度→2周目の勝利まで確認してください。

## 画面はあるのに初めから反応しない SyntaxError

敵名の行から値だけを消し、次の状態にしました。

```js
const enemyName = ;
```

Consoleには `SyntaxError: Unexpected token ';'` が出ました。見出し、HP 24／18、ボタンは表示されたままで、敵名だけが空欄でした。「たたかう」「もう一度」を押しても表示は変わりませんでした。このファイルではJavaScriptの解析に失敗し、敵名の設定やクリック処理の登録が始まりません。HTMLに直接書いた文字やボタンまで消えるわけではありません。

この例の修正は、値を戻す1行です。

```js
const enemyName = "スライム";
```

修正版を読み直すと、敵名が表示され、リセット後の2周目まで動きました。別のコードで同じエラーが出たときは、示された行と直前の行の値、引用符、括弧を確認します。エラー位置が原因の位置と一致するとは限りません。[MDNの構文エラー解説](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Errors/Unexpected_token)

## 敵名は出るのにボタンが反応しない null と TypeError

HTMLのボタンは `id="fight"` のまま、取得する行だけを変えました。

```js
const fight = document.querySelector("#attack");
```

`document.querySelector("#attack")` の結果は `null` でした。Consoleには `TypeError: Cannot read properties of null (reading 'addEventListener')` が出ました。敵名の「スライム」は表示されますが、攻撃もリセットも反応しません。敵名の設定はエラーより前に実行され、リセット処理の登録はエラーより後にあるためです。

ボタンのIDと一致する `document.querySelector("#fight")` へ戻すと、2周目まで動きました。[querySelectorは一致する要素がなければnullを返します。](https://developer.mozilla.org/en-US/docs/Web/API/Document/querySelector)

`null` だけでIDの誤りとは断定できません。要素がまだ読み込まれていない場合も確認対象です。ただし今回の掲載例は、ボタンを書いた後、`</body>` の直前にscriptがあり、読み込み待ちを追加せず、セレクター1か所を戻して修復できました。IDが違うまま `DOMContentLoaded` を加えても一致する要素は生まれません。[DOM読み込みとscriptの配置](https://developer.mozilla.org/en-US/docs/Web/API/Document/DOMContentLoaded_event)

## 1回目は勝てるのに遊び直せない エラーのない不具合

「もう一度」の処理から、次の1行だけを削除しました。

```js
fight.disabled = false;
```

1周目は3回攻撃して勝てました。「もう一度」を押すとHPと案内文は初期表示に戻りますが、攻撃ボタンは無効なままです。ボタン位置を普通にクリックしてもHPは変わらず、Consoleに例外も出ませんでした。エラーがないことだけでは、遊び直せると判断できません。[disabledのボタンは通常のクリック操作を受け付けません。](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/disabled)

修正は、リセット処理へ `fight.disabled = false;` を戻すことです。勝利時の `fight.disabled = true;` は残します。修正版では勝利後に攻撃が止まり、リセットすると再び攻撃でき、2周目も勝てました。画面を再読み込みするだけでも一時的に攻撃できますが、修正前のファイルでは次の勝利→リセットで同じ不具合が残ります。

## AIへ渡す情報は小さく、修正後の確認は最後まで

Consoleを開いた状態でファイルを読み直し、最初のエラーと操作順を記録します。GameBuildiaryの表示枠を使っている場合は、コードを直した後に「ゲームを表示」で実行する版も更新します。以下は、今回のリセット不具合を相談するときの例です。

```text
1回目は「たたかう」3回で勝てます。
その後「もう一度」を押すとHPは24／18に戻りますが、攻撃できません。
期待: リセット後は攻撃でき、2回目も勝利まで遊べる。
実際: fight.disabled は true のまま。Consoleに例外は出ません。
関連コード: 勝利時とリセット時の処理、ボタンのHTMLだけを添付します。
依頼: 原因と最小限の変更箇所を説明してください。
勝利後の攻撃停止は残し、リセット後だけ再び攻撃できるようにしてください。
```

APIキー、トークン、Cookie、個人情報、非公開URLや個人のフォルダー名は除いてください。まず症状に関係するHTMLと処理だけを渡し、不足する箇所が判明してから追加します。修正を採用する前に、再読み込み、初回の勝利、リセット、2周目の勝利、Consoleを確認し、動いた版を保存します。

## この検証の範囲

2026年10月11日、LinuxのChromium 151.0.7922.173をPlaywrightから実行し、ローカルHTTPで各HTMLを開きました。画面幅1280／375／320pxで確認しています。375pxではページ幅が380px、320pxでは328pxとなり、小さな横方向のはみ出しがありました。操作はできましたが、この元版をスマートフォン表示の合格とはしていません。また、この見た目では無効になった攻撃ボタンも緑色のままで、色だけでは状態を見分けられません。

元版とは別のコピーに、`main` のCSSへ `box-sizing: border-box;` を1か所追加して再検証しました。幅の指定に左右の余白と枠線を含める修正です。修正コピーでは375pxと320pxのページ幅がそれぞれ375pxと320pxに収まり、3種類の意図的な不具合と修正版を含む同じ21ケースの機能結果も変わりませんでした。掲載記事と元の検証ファイルは変更していません。この幅修正はJavaScriptの3不具合とは別の修正です。320pxでは見出し末尾の「ル」が次行へ折り返されるため、表示全体の合格とはしていません。

スマートフォン幅はブラウザーの表示幅を変えた確認で、実機のタッチやファイル操作、Safari／Firefox、GameBuildiary表示枠内のエラー表示は検証していません。

今回のコードは外部ファイルを使わない単一HTMLです。外部モジュールの読み込みは今回の不具合の原因ではありません。モジュールを使う別のゲームで `file://` による読み込みエラーがある場合は、[MDNのモジュール解説](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Modules)を確認し、ローカルサーバーで試してください。ブラウザーの保護設定を解除する手順は必要ありません。この草稿では外部モジュールの実験結果を扱いません。
